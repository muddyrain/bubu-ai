# Bubu AI · Workbench V1.2 · UI 设计交付规范

> 日期：2026-10-26 ｜状态：**整体 UI 布局与交互已获 Owner 认可**，实际角色原图和实现截图须单独 Review。
>
> 边界：纯本地 HTML 原型只呈现 UI 与演示数据；没有接入模型、读取用户真实文件、执行文件修改、授权或同步。
>
> 产品基线：`PRD-v0.1.md`。采用“一二布布原版角色素材 + 可组件化的桌面三栏工作台”，不使用任何 AI 重画的一二布布角色形象。

## 1. 产品定义

**产品定位**：本地优先的桌面 AI 文件工作台，用户以对话驱动文件查找、读取理解、分类整理，系统将危险变更转为可审查的计划，获取明确授权后才执行。

**V0.1 唯一核心任务链路**：
1. 连接具备对应能力的模型供应商；
2. 用户通过系统目录选择器授权一个本地目录；
3. 用户以自然语言搜索、读取或整理该目录中的文件；
4. 文件整理走「扫描 → 规则解析 → 预览计划 → 审批 → 逐项执行 → 核对」；
5. 任务结束展示真实的成功、跳过、失败信息及日志。

**必须遵循的规则**：不默认读取整个磁盘、不允许跨授权边界操作、不静默删除、不覆盖同名文件、不使用假进度、不把模型回复本身当成执行结果。

**不做**：截图控制电脑、鼠标键盘接管、浏览器自动化、PDF/DOCX 正文解析、自动删除、复杂 RAG、定时工作流、完整撤销 UI、多 Agent 角色编排。文件整理中的按扩展名分类使用确定性 Node.js 规则，模型负责理解意图与选用规则，不逐文件“猜分类”。

## 2. 工作台布局（Desktop）

参考视口：**1440 × 900 CSS px**，最小建议有效应用窗口 **1024 × 720 CSS px**。

```text
┌──────────────────── Window frame 1400 × 866 ─────────────────────────┐
│ TitleBar 58 ─ Brand / Breadcrumb ─ Status / Review-only switch       │
├──────────────┬─────────────────────────────────┬─────────────────────┤
│ Sidebar 216  │ ChatWorkspace (flex:1 ≈830)     │ ContextPanel 354    │
│              │ Header 55                        │ Header 55           │
│ Navigation   ├─────────────────────────────────┤                     │
│ Sessions     │ Scrollable conversation         │ Scrollable content  │
│              │ Welcome / Messages / Task Cards │ Scopes / Steps /    │
│ Mascot card  │                                 │ Plan rows / Results │
│              ├─────────────────────────────────┤                     │
│              │ Sticky composer (auto, ~148)    ├─────────────────────┤
│              │                                 │ Fixed approval CTA  │
└──────────────┴─────────────────────────────────┴─────────────────────┘
```

| 区域 | 规格 | 溢出、折叠规则 |
|---|---|---|
| Window shell | 视口四周水平 20、垂直 17；R22 | Electron 生产版按当前 OS 使用原生/自定义窗口控制，示例红黄绿圆点只是视觉预览 |
| TitleBar | H58 | 仅在设计预览中出现的“状态切换”控件，生产版必须移除 |
| Sidebar | W216 | 1060px 以下缩为 70px 图标栏；导航按钮 H43 |
| Center | `flex:1`, `min-width:0` | 会话内容独立纵向滚动；欢迎 Banner 仅在空态展示 |
| Chat header | H55 | 标题、任务状态、右侧面板显示开关 |
| ContextPanel | W354 | 1250px 以下 W318；1060px 以下 W296；可通过 UI 隐藏/恢复 |
| Context header | H55 | 状态对应标题；审批时不能遮挡操作清单 |
| Composer | 底部固定、内容自动高度 | textarea 多行；模型选择、添加文件、授权入口；不可被任务长内容推出视窗 |
| Approval footer | 底部固定，按钮≥38px | 右侧操作清单独立滚动，全量路径可展开，确认 CTA 始终可见 |

小窗口策略：1024×720 优先保证聊天和审批按钮可见，导航缩图标；无法兼容的更窄宽度应将右侧变为可打开的抽屉，而不是无限压缩正文。应用实际最小宽度需在目标 OS 验收后固定。

## 3. 视觉设计 Token

色彩采用「暖奶油 + 焦糖棕」，但**正文优先可读性**，不要使用低对比度浅咖文字替代正文。

| Token | 色值 | 用途 |
|---|---|---|
| `--bubu-bg` | `#F6F0E9` | 窗口外背景 |
| `--bubu-surface` | `#FFFDFA` | 内容面 |
| `--bubu-surface-soft` | `#F5E8DE` | 聊天气泡/导航 hover |
| `--bubu-text` | `#48362D` | 主要文字 |
| `--bubu-muted` | `#79665B` | 次要说明 |
| `--bubu-accent` | `#9B654A` | 主按钮、选中状态 |
| `--bubu-accent-hover` | `#865139` | 主按钮 hover |
| `--bubu-border` | `#EADED4` | 边框 |
| `--bubu-success` | `#4C916D` | 成功 |
| `--bubu-warning` | `#B16F3E` | 待审批/冲突 |
| `--bubu-error` | `#C65B54` | 失败 |

字体：优先系统中文 sans（PingFang SC、Microsoft YaHei、Noto Sans CJK SC），**正文 14px / 1.6**，页面标题 20–24px，组件标题 14–16px；说明通常 12px，重要确认和错误不能缩到 10px。大号欢迎标题可用衬线字体作视觉点缀，不能要求下载不明许可字体。

间距：4pt 单位，常用 `4 / 8 / 12 / 16 / 20 / 24 / 32`；卡片 R14–18、主 Banner R22；按钮 H38–40，图标建议 18px，鼠标可点目标建议至少 36×36。

### 角色素材占位规则

- Hero：欢迎空态使用单张或双角色独立透明 PNG/GIF，首选不遮挡标题的布局；最大显示区域约 320×200px，按真实宽高比 `object-fit:contain`。
- Chat avatar：32×32px；Sidebar 小角色：≤110×80px；任务插画：80–110px；审批页不使用大插画。
- **禁止**通过变形拉伸、AI 自动修改五官、叠加未知滤镜重新描画一二布布。
- 原型采用用户提供的 **92×92 低清参考图裁剪图**，用于展示“图片与 UI 分层”的工程结构，**不是可发布的角色资产**。高清原版 PNG/GIF 按 `ASSET-HANDOFF.md` 替换即可。

## 4. 五种主界面设计

### W01 — Welcome / 未配置

- 入口：初次启动、显式新建会话且无消息。
- Center：一二布布欢迎插画（独立图片）、简短说明、三个有用途的任务示例。首次欢迎时大插画出现；进入任何任务后收起。
- Right：三步引导：①连接支持所需能力的模型 ②授权本地目录 ③发起文件任务；隐私说明。
- CTA：添加模型、选择目录；在未经配置/授权时不显示真实目录文件树，不假装成功。
- 异常：无供应商、API 测试失败、用户拒绝目录授权，明确展示原因及重试入口。

### W02 — Chat / 搜索和读取文件

- 入口：用户正常聊天或请求查询本地已授权文件。
- Center：会话流、回答、`FileSearchResultCard`（文件名/路径/匹配理由/定位）；文本阅读结果要清楚提示来源。
- Right：当前授权目录、权限等级、结果统计及检索摘要；用户可收起右栏。
- 交互：点击定位 → 受控 IPC 打开系统文件管理器。云端模型接收原始本地文件内容时需要明确的发送告知/授权。
- 异常：无匹配结果、工具不可用、格式不支持、文件在搜索后被移动、网络中断、模型不支持 Tool Calling。

### W03 — Analyzing / 正在分析

- 入口：Run 进入 `scanning` 或 `planning`，尚未执行任何写操作。
- Center：任务目标、真实工具事件时间线，显示完成/进行/待运行步骤；如有实际计数，以 `processed / total` 展示。
- Right：授权目录、文件数、当前步骤、停止按钮；不可量化的模型计划生成仅显示“正在生成”，不要伪造百分比。
- 交互：停止分析进入 cancelled；成功生成计划进入 W04；失败进入明确错误状态（通常可复用 W05 外壳但需要失败文案）。
- 审核点：不要把预览扫描当成已经修改文件。

### W04 — Approval / 整理方案审批

- 入口：生成结构化 plan，成功通过源路径、目标路径和冲突校验，Run=`awaiting_approval`。
- Center：AI 用自然语言解释计划摘要：“预计移动 6、冲突跳过 1、不删除、不覆盖”。
- Right：授权源目录、待移动统计、冲突说明；完整逐文件列表（每项可**展开完整源/目标路径**）；底部固定「取消 / 确认执行」。
- V0.1 只支持**整份计划审批或拒绝**；想修改规则，重新输入请求生成新计划，不给未实现的“单行选择”错觉。
- **审批约束**：`planId + version + digest` 绑定批准内容；用户审批后，执行器仍逐项重新验证文件状态与权限；前端 disabled/loading 不取代后端幂等与安全校验。
- 异常：目录授权被收回、计划过期/文件已变化、目标冲突变多、用户审批超时、重复提交；必须重新生成或拒绝，不静默扩权。

### W05 — Result / 完成、部分完成或失败

- 入口：执行器结束或任务取消后整理实际结果。
- Center：基于操作日志汇总成功/跳过/失败，附“打开目标目录”入口。仅在全部计划操作按预期结束时显示“完成”。
- Right：可滚动的逐文件执行记录；跳过必须显示原因；失败要允许复制错误信息。
- 完成与失败互斥状态：`completed` / `partially_completed` / `failed` / `cancelled`，文案和角色状态不能一律显示庆祝。
- V0.1 暂不承诺“任何操作一键撤销”；明确限制，先完整记录可审查的变更日志。

### Supporting — File Space / 辅助页面（非第六个主任务状态）

- 导航中的“文件空间”必须打开真实的文件浏览和授权范围视图，而不是跳回聊天。
- 演示中使用模拟笔记列表。生产中仅访问授权目录；支持搜索、查看文件信息、跳转文件位置；不通过文件列表悄悄修改文件。

## 5. 状态驱动与角色映射

```text
unconfigured → idle → scanning → planning → awaiting_approval
                    ↘ cancelled / failed       ↘ rejected
awaiting_approval --用户批准有效 plan--> executing → verifying → completed
                                                       ↘ partially_completed / failed
```

`scanning`/`planning` 复用 W03 视觉，`executing` 也使用执行时间线，但**必须显示写入中状态与停止影响说明**；`verifying` 不做假进度；`completed` 等终态复用 W05 组件。

| Run 状态 | RoleState | 前端表现 |
|---|---|---|
| idle / unconfigured | `idle` | 原版欢迎 PNG/GIF，静态优先 |
| scanning / searching | `searching` | 找文件表情，最多轻微 CSS 动画 |
| planning | `thinking` | 思考/写字动图 |
| awaiting_approval | `waiting` | 安静提示等待，无连续闪烁 |
| executing / verifying | `working` | 工作中，信息优先、角色缩小 |
| completed | `success` | 一次性完成动效 |
| failed / cancelled / partially_completed | `error` 或 `neutral` | 不展示“全部成功”庆祝 |

开启 `prefers-reduced-motion` 时，禁用不必要动画。角色图片不能替代文本状态或进度。

## 6. 状态交互约束

1. UI 发送结构化意图，**不**通过渲染进程直接访问 `fs` 或任意 IPC 通道。
2. FileTool 结果带来源、数据版本和是否已授权信息，React 只消费经过主进程验证的数据。
3. 搜索和扫描允许实时结果；完整重排必须预览并由用户审批。
4. 文件计划变动时审批失效，必须重新显示 diff/计划版本。
5. 正在执行时“停止”不等于回滚，必须说明已有操作可能已完成并可在记录中查看。
6. 工具调用超过上限、任务取消、授权失效、云模型切换都必须有可见状态，不能无限 loading。
7. 重连/页面刷新后通过 Run 快照恢复 UI；展示不确定状态不能臆测成功。
8. 云模型发送本地文件内容前需要清楚标出实际接收供应商、内容范围及目的，用户能拒绝。
9. 本地模型、云模型、多供应商切换时，工具可用性应依据实际模型能力，而非 UI 假设。
10. 使用原版一二布布素材时记录来源和使用前提；代码许可与角色素材许可必须分别说明。

## 7. 组件交付验收

- 所有可交互内容由 React 组件构成，绝不把截图作为界面背景。
- 所有图片有独立路径、自然宽高和 Alt；角色原图宽高比保留。
- 1440×900、1100×800、1024×720 下没有水平溢出；聊天主体、审批列表各自可滚动。
- 批量计划 1000 项时不能阻塞 UI，应采用虚拟滚动或分页。
- 非长路径不可意外省略；长路径允许折叠，但必须能够展开查看完整值、复制。
- 中文 IME 输入不应在拼音合成过程中触发发送；`Enter` / `Shift+Enter` 规则要明确并测试。
- 正常 Tab 顺序、可见焦点、`Escape` 关闭非破坏性弹窗、完成/错误状态可被辅助技术理解。
- 主体/核心控件按 WCAG AA 对比度验收，动画遵守减少动态效果偏好。

## 8. 实施与发布边界

交付的 `reference/preview.html` 是无依赖、离线可打开的交互评审稿，顶部状态切换和按钮均为演示动作，**绝不会读写真实文件**。原型所需的 CSS、JS 和低清参考图已内嵌在 `reference/preview.html` 中。Codex 需按照本文组件契约重建 React UI，不得把 mock 状态与真实 Runtime 混用。

**冻结规则**：此次评审认可后可以冻结布局、组件结构和交互规范；角色高清 PNG/GIF 的落地仍需换成已选原版文件，在真实操作系统上完成视觉检查与使用条件记录。
