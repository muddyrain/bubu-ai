# 功能文档模板（仅用于新增长期稳定的功能域）

> **不是每做一个 Issue 都要复制本模板。** 只有出现新的独立用户能力、且现有 `docs/features/` 无合适文档时才新建。

```markdown
# 功能名

> 状态：planned | in-progress | implemented
> 版本：V0.1 / V0.2 ...
> 对应模块：实际路径（若已实现）

## 用户为什么需要
用一句话描述真实价值和主要用户场景。

## 用户怎样使用
入口、流程、正常情况、重要 UI 状态。

## 能力与边界
已支持的行为、未支持的行为，按真实实现维护；不要写营销承诺。

## 权限与数据
用户授权方式、数据读写/外发规则、失败默认策略。

## 错误与特殊情况
典型异常、取消/重试/冲突等的准确行为。

## 技术实现摘要
核心模块职责、事件/持久化契约；链接架构文档，避免复制完整设计。

## 验收与测试
真实测试用例/测试文件链接；尚未实现时注明计划的验收标准。
```
