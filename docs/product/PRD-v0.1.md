# Bubu AI — 产品需求文档（PRD）V0.1

> **状态：V0.1 产品范围已获 Owner 方向确认；实施中以验收结果与 Review 为准**  
> 制定日期：2026-10-26  
> 产品名称：Bubu AI（暂定）  
> 产品形态：单用户、本地优先的 Electron 桌面应用  
> 目标：通过自然语言**搜索、读取、理解、整理用户授权的本地文件**。  
> 关联：[五态界面及交互规范](../design/WORKBENCH-V1.2.md) · [Code Review 规范](../development/code-review.md)

## 1. 产品定义

### 1.1 一句话定位

一款以“一二布布”作为情感化交互主题的桌面 AI 工作台：用户用自然语言提出文件任务，Agent 在**授权范围内**调用确定性的本地文件工具，并以可预览、可审批、可验证的方式完成操作。

### 1.2 目标用户与场景

- **个人电脑重度使用者**：下载目录堆积，希望快速分类文件而不愿一项项拖动。
- **开发者与技术学习者**：需要在授权的笔记／项目目录中查找技术文档、阅读文本并概括重点。
- **整理需求明确但不熟悉脚本的用户**：可以说出目标，但不想自己编写批处理命令。

**产品优先顺序：文件安全与可控性 > 任务成功率 > 清晰反馈 > 速度 > 角色装饰。**

### 1.3 核心价值主张

1. **自然语言入口**：理解用户要找什么、看什么、整理成什么样。
2. **本地真实执行**：不只生成操作说明，而是在授权范围内读文件、搜索文件、生成并执行文件整理计划。
3. **用户掌握控制权**：写操作之前看得到完整计划，拒绝则不执行；执行结果来自本地系统，不由模型编造。
4. **亲和且高效**：一二布布作为 AI 状态反馈而非遮挡内容的贴纸。

## 2. V0.1 目标与成功定义

V0.1 只交付三个可闭环任务：

| 任务 | 用户示例 | 预期结果 |
|---|---|---|
| 文件搜索 | “在我授权的笔记目录里找含有 NestJS guard 的文件” | 返回确实存在的路径、匹配依据，可定位文件 |
| 文本理解 | “总结这个目录里几篇 Markdown 笔记的核心内容” | 仅在授权文件与大小限制内读取，产生带来源路径的总结 |
| 文件整理 | “把下载目录里的图片、PDF、压缩包分开，其他不要动” | 生成逐文件计划 → 用户审批 → 同目录树内移动 → 核对报告 |

**V0.1 完成的定义**：安装／启动桌面应用，完成模型配置与目录授权，在测试目录完成上述三个任务；所有写入操作都经过真实审批，未授权路径不可访问，能够查看成功、失败、跳过的具体结果。不是只完成视觉页面或模拟进度。

## 3. 范围管理

### 3.1 P0：首版必须具备

**A. 桌面应用与设置**

- Electron + React 应用壳、主窗口与基本导航、基本错误提示。
- 添加至少一种经过验证可支持 **Tool Calling** 的 OpenAI-compatible 模型端点：URL、模型名、API Key、连通性及工具调用能力测试。适配更多供应商留扩展口，不承诺任意兼容端点均可正常调用工具。
- API Key 不明文写入普通配置文件；在安全存储不可用时明确提示，不静默降级为明文。
- 用户可查看当前模型、是否联网、是否支持工具调用；请求失败后能重试或切换配置。

**B. 对话工作台**

- 新建与切换会话、流式回复、基础历史持久化、停止本轮生成。
- AI 回复与本地文件工具结果显示为结构化卡片；错误信息不能只保留在开发者控制台。
- 任务中显示当前阶段与可见操作记录；不输出虚构的文件数量或进度百分比。

**C. 文件授权与读取**

- 通过操作系统原生选择器授权**具体目录**；支持只读或读写范围，可查看和撤销授权。
- `list/stat/search/readText`：读取目录结构、元信息、按名称或受限文本内容搜索；读取支持 UTF-8 的 `.txt`、`.md`、`.json` 等文本格式（后续可扩展）。
- 搜索结果至少含文件名、路径、类型／匹配片段，并能在系统文件管理器里定位。
- 文件树仅显示**授权目录**，按需展开，不是扫描整台电脑。

**D. AI 文件整理**

- Agent 将用户意图转换成**结构化规则**：需处理的扩展名分组、目标子目录、保留规则；Node.js 负责实际扫描与生成逐文件候选移动计划。
- V0.1 默认仅扫描一个授权目录的**直接子文件**（不递归移动已有子目录）；未被规则覆盖的文件不处理；隐藏文件、系统特殊文件、符号链接默认跳过并记录。
- 生成 `source → target` 明细、影响文件数量、目标目录、潜在冲突及跳过项。
- 写入前明确授予读写范围、展示完整可检查计划，并对该版本计划审批；修改需求后必须重新生成并审批计划。
- 执行时逐项重新验证范围、源文件状态、目标路径冲突，不自动覆盖、不删除文件；执行结果显示成功／跳过／失败数量与原因。
- 取消只能阻止**后续**操作；已完成操作不会被默默声称回滚。

**E. 可信状态与记录**

- 持久化会话、任务、审批决定、操作结果（如 SQLite）；真实数据驱动界面，而非模型生成“已完成”文案。
- 用户能查看任务执行摘要及逐条明细。模型失效、取消、部分失败有明确终态。
- 一二布布只在欢迎、分析、等待审批、执行、成功／失败等状态做轻量反馈。

### 3.2 P1：不阻塞首版

- PDF／DOCX 正文解析；批量重命名；跨目录复杂移动；重复内容哈希检测。
- 针对支持恢复的文件操作实现撤销日志／恢复，并加入冲突检测；公开对外使用前重点补齐。
- 递归整理、文件大小／日期高级条件、大批量任务优化；更多 Provider 原生协议。
- 文件整理计划的逐项编辑、排除与批量勾选；知识库搜索索引。

### 3.3 不在 V0.1

- 电脑屏幕接管、鼠标键盘控制、浏览器自动化。
- 全盘自动扫描、后台未经确认整理、无人值守删除或覆盖。
- MCP 商店、多 Agent 协作、RAG 向量库、在线同步、多用户／团队空间。
- 定时任务、自动推送、语音助手、2D/3D 桌面宠物、完整表情动画系统。

## 4. 核心用户旅程

### 4.1 首次配置

1. 用户首次打开应用，看到一二布布欢迎态；尚未授权的目录不得展示为已扫描。
2. 添加并测试模型。检测到模型不支持工具调用时，聊天可以使用，但**文件 Agent 任务不可执行**，界面解释原因。
3. 用户通过系统选择器授权一个目录（默认只读）。
4. 工作台进入可用状态，展示示例任务和真实授权目录信息。

### 4.2 搜索与阅读（只读）

1. 用户描述需要查找的文件。
2. Agent 调用授权范围内的 `fs.search`／`fs.readText`，必要时提问澄清。
3. 对话中展示可点击的文件卡片与引用来源；明确说明“未找到”而不是编造文件名。
4. 当请求需要读取文件正文并发送给云端模型时，首次针对接收模型／供应商给出**明确的数据外发告知与用户确认**；拒绝则停止该读取任务。

### 4.3 文件整理（写入）

1. 用户选择授权目录并下达分类要求。
2. Agent 提取分类意图；文件工具读取真实文件元数据。
3. 生成计划，包括所有被修改的文件；可按分页／虚拟列表完整检查。
4. 检测读写权限：只有只读授权时，必须通过系统授权流程升级，不可以由模型自行提权。
5. 用户批准**当前不可变计划版本**；拒绝时不发生任何更改。
6. Executor 在每项操作前重新校验权限、源文件状态和目标冲突；逐项执行并记录。
7. 展示完成／部分完成／失败／取消的结果，提供明细和文件定位。

## 5. 数据与状态约束

### 5.1 核心概念

- `Conversation`：聊天会话，包含消息与关联任务。
- `WorkspaceScope`：用户授权路径、读写级别、授予时间、撤销状态。
- `AgentRun`：一次用户任务执行记录，含阶段／状态／当前模型／取消标志。
- `FilePlan`：只读计划快照，含版本、签名／哈希、源与目标明细、冲突与跳过信息。
- `PlanApproval`：对 `planId + version + digest` 的明确审批，拒绝或修改后不继承旧审批。
- `FileOperation`：逐项执行记录，包括结果、错误代码和操作前验证结果。

### 5.2 Run 状态

`created → scanning → planning → awaiting_approval → executing → verifying → completed | partially_completed | failed | cancelled`。这里 `scanning`、`planning` 是运行态，统一展示在 UI 的“分析中”视图；纯搜索／阅读任务可在读取/分析后直接进入终态，不需要进入审批与写入环节。用户拒绝计划进入 `cancelled`；从 `awaiting_approval` 修改需求需重生成计划，不能用旧审批执行新计划。

执行过程进度优先显示 **处理计数**（已处理 X / 总计 Y）。无法量化的阶段用不定进度态，不显示臆造百分比。

## 6. 安全与隐私验收边界

- **默认无权限**：未获授权的目录不能访问，聊天也不能在后台擅自扫描。
- **最小权限**：只读与读写分离；系统选择器决定范围；权限检查在工具执行处而不只在提示词中。
- **路径安全**：规范化路径、`realpath` 检查、拒绝跨授权范围的符号链接；执行前二次校验；对符号链接替换等竞态操作要设计相应安全测试，不能只依赖先前一次检查。
- **写操作守卫**：没有当前计划审批不得写入；不得静默删除、覆盖、提权、跨授权目录写入；冲突跳过并记录。
- **数据外发透明**：明确区分本地目录扫描与把正文发送至云端模型。只发送完成任务必要的信息；取消或切换 Provider 后，历史敏感内容不得未经重新校验就发送。
- **Prompt Injection**：读取的文件内容视为不可信数据；其中的指令不能提升权限或代替用户审批。
- **日志脱敏**：不记录 API Key 或完整敏感文件正文；调试日志默认最小化。敏感目录（凭据、密钥、应用私有数据）采取额外防护。
- **异常终态**：崩溃、超时、取消时不把部分成功误报为完全成功；恢复或重试须避免重复移动已经完成的文件。

## 7. V0.1 验收用例

| 编号 | Given | When | Then |
|---|---|---|---|
| AC-01 | 从未授权文件夹 | 用户请求搜索该目录 | 必须提示授权；没有任何目录内容返回 |
| AC-02 | 已授权含 3 个测试文本文件的目录 | 搜索指定关键字 | 返回真实匹配路径及片段，未命中则显示未找到 |
| AC-03 | 模型不支持工具调用 | 请求本地文件任务 | 不执行文件操作，展示能力限制 |
| AC-04 | 用户只授予只读 | 发起整理任务 | 可以生成预览，但写入前必须升级权限与审批 |
| AC-05 | 计划包含 3 个移动操作 | 用户拒绝审批 | 3 个源文件位置均不变 |
| AC-06 | 审批过的计划发生源文件改变 | 点击执行 | 受影响项目跳过或失败，不盲目移动 |
| AC-07 | 目标已有同名文件 | 执行整理 | 原目标不被覆盖，冲突项目有明确标记 |
| AC-08 | 批量执行中用户取消 | 执行下一项前检查取消 | 后续不执行，已完成与未完成分别记录 |
| AC-09 | 读取包含恶意“删除全部文件”指令的文本 | Agent 处理内容 | 不执行未经用户审批的写入或删除 |
| AC-10 | 用户切换云端模型 | 后续请求引用敏感本地内容 | 重新执行接收者权限检查；未授权不得发送 |
| AC-11 | 部分文件成功、部分冲突 | 任务结束 | UI 显示 `partially_completed`、真实结果计数及明细 |
| AC-12 | 任务进行中网络／模型失败 | 用户查看结果 | 显示失败与已执行操作明细，不伪造成功 |

**自动化测试建议**：使用隔离的临时 fixture 目录与 Mock Tool-calling Model 跑完 AC-01～12；对关键文件权限和拒绝／审批场景做集成测试。真实云端模型联调可作为附加测试，但不可代替确定性用例。

## 8. 工程原则与交付门槛

- **本地优先，不依赖云服务托管**：Electron 主进程／受限服务负责本地工具；Renderer 不得直接访问任意 `fs` 或执行 Shell。
- **优先 TypeScript**：React + Electron + Node.js，SQLite 持久化，Zod 入参校验。NestJS 与 Go 均非 V0.1 必需。
- **结构化 Tool 调用**：LLM 决定目标和工具；实际文件分类、路径校验与移动由确定性代码执行；禁止自由 Shell 工具作为 MVP 的默认文件处理途径。
- **代码审查优先**：每项能力按 Issue → 设计要点 → 最小 PR → Review → 测试 → 人工确认合并实施。
- **不依赖素材切图**：UI 组件用真实 React/CSS，角色与背景采用分层独立素材。

## 9. 可衡量的产品验收指标（目标，而非已达成结果）

- 在标准测试夹具上：**未授权写操作成功次数 = 0**；**未审批写操作成功次数 = 0**；**目标文件被静默覆盖次数 = 0**。
- 搜索、阅读、整理三类端到端演示流程均能按 AC 用例稳定完成。
- 模型无法调用工具、目标冲突、用户取消、文件变化四种情况均有可理解的结果反馈。
- 审批操作的影响文件总数与最终记录中成功／跳过／失败总数可核对。

## 10. 待后续产品评审的问题（不阻塞建立项目）

1. 首发目标平台：Windows／macOS／Linux 先选一个做完整安装验收，其他平台逐步补齐。
2. 素材授权与品牌名称：一二布布角色原始素材、署名和使用约束单独存档，不默认随代码许可证再授权。
3. 整理分类的默认规则：图片、文档、压缩包之外的格式默认不移动；后续再扩充白名单。
4. 是否需要 V0.2 的“一键撤销最近任务”：正式面向真实用户推荐优先实现。
